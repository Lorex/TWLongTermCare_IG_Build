## 規劃重點

| 賽道編號與名稱 | 代表情境與資源 | 實作與驗證安排 |
|---|---|---|
| Track 0 OAuth2 存取認證 | 授權碼取得（LTC-011）與受保護資源存取（LTC-012） | 共通前置基礎；驗證 Bearer Token 有效性與缺少 Token 時之 401 回應 |
| Track 1 長照共通資料交換 | 9 項共通基礎資源（病人基本資料、機構基本資料、生理量測、用藥紀錄四項必測；健康問題、目標、計畫、服務請求、照護執行紀錄選測） | 聚焦頂層 LTC 資源建立與查讀；每情境包含 Creator 建立（POST）與 Consumer 查讀（GET）；廠商必須完成 SC1 至 SC4 四項必測（LTC-111 至 LTC-142），SC5 至 SC9 依產品能力選測（LTC-151 至 LTC-192） |
| Track 2 居家照護資料交換 | 居護個案基本資料（SC1，必測）、全人評估（SC2，選測）、照護計畫（SC3，選測）與共照記錄（SC4，選測）表單與計畫資源新增與查讀 | 廠商完成 SC1 必測（POST LTC-211 或 GET LTC-212），並自 SC2 至 SC4 至少選測一項（LTC-221/222、LTC-231/232、LTC-241/242）；銜接 Track 1 LTC-112 查讀能力 |
| Track 3 長照費用支付審核 | BA07 服務費用申報（Claim）與審核結果（ClaimResponse） | 廠商提交單筆費用申報（POST LTC-311），大會模擬審核服務產出結果後由廠商查讀（GET LTC-312）；銜接 Track 1 LTC-112 與 LTC-122 查讀能力 |
| Track 4 在宅急症照護資料交換 | 初次訪視與收案（SC1）、持續訪視與急症治療（SC2）、後續照護安排與交班（SC3） | 20 筆業務交易，各資源逐筆建立與查讀；廠商依報名角色與臨床職責配對完成流程，必測 SC1 411–414、SC2 421/422 加 423/424（處方給藥）或 427/428（在宅處置）、SC3 431/432 及 435/436，其餘為選測，逐交易與 Resource 記錄實作能力 |

## 會前測資準備

大會於會前備妥標準測試資料與端點環境，以降低現場除錯時間：

1. **基礎個案與相依資源預載**：大會預載符合 Profile 規範之必要參照資源（特約機構、照護與醫事人員、給付資料以及在宅急症收案療程與就醫紀錄等）。長照共通資料交換受測主要資源由 Creator 當次建立，大會提供固定合成案例、JSON 範本與唯一識別碼。
2. **問卷與相依資源發布**：發布居護個案基本資料（`http://ltc-ig.fhir.tw/Questionnaire/hn-basedata`）、全人評估（`http://ltc-ig.fhir.tw/Questionnaire/hn-healthyhabits`）與共照記錄（`http://ltc-ig.fhir.tw/Questionnaire/hn-casedesc`）問卷定義、相關代碼系統，以及照護計畫所需預載之 HNGoal 與來源表單參照。
3. **前置格式驗證**：大會提供之測資均通過 HL7 FHIR Validator 檢驗，確保欄位基數、型別與約束條件合規。

## 廠商分工與共同案例

依聯測規劃招募長照個管、機構管理、生理量測設備、申報介接、電子病歷及在宅醫療系統廠商參與：

1. **跨角色配對協作**：由管理端（LTC_MANAGEMENT）發起單筆新增，資料儲存端（LTC_REPOSITORY）接收儲存，資料查詢端（LTC_CONSUMER）發起條件查詢與單筆讀取，驗證跨系統資料一致性。
2. **必測與選測安排**：Track 1 廠商必須完成 SC1 至 SC4 四項核心必測，並可選測 SC5 至 SC9；Track 2 廠商必須完成 SC1 居護個案基本資料管理（必測），並自 SC2 全人評估管理、SC3 照護計畫管理與 SC4 共照記錄管理中至少選測一項，依所選角色完成驗收；Track 4 廠商依報名角色與臨床職責配對完成 SC1 初次訪視與收案（411–414）、SC2 持續訪視與治療（421/422 加 423/424 或 427/428）及 SC3 後續照護安排與交班（431/432 及 435/436），其餘為選測。
3. **驗收紀錄保存**：每筆驗收紀錄保存年度、賽道、情境、交易 ID、參測系統、角色、請求與回應內容及欄位比對成果。
