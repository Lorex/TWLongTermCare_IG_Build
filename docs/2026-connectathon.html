活動資訊 (Event Information)

活動名稱： 2026 臺灣長期照顧 FHIR 專案聯測松 (2026 TW Long-Term Care FHIR Projectathon)

時間： 2026/10/29 (四) 下午 至 2026/10/30 (五) 全日，共 1.5 天（10/29 13:30–16:30、10/30 10:00–16:30）

地點： 民生科技服務大樓 2 樓 Living Lab+ (臺北市松山區民生東路四段 133 號) 地圖連結

報名資訊： 本活動免費報名，名額 25 名，報名截止時間為 2026/10/23 18:00，詳情請參閱 活動資訊與報名。

進行模式：

  • 聯測共辦理 1.5 日，參測單位依產品功能選擇賽道與角色，並依各賽道規定完成必測與選測項目。
  • 各賽道列有操作步驟、檢核項目與通過條件，參測單位依報名角色與配對系統共同完成驗收。
  • 大會事前公布賽道檢核內容、測試資料與測試環境，並提供標準 FHIR 伺服器供連線演練。
  • 參測單位可於會前完成系統實作與預演，測試過程中如有問題可即時回報進行釐清。
  • 聯測配置督察員檢核廠商產品是否符合規範，完成聯測後將成果公告於活動網站。

系列相關活動：

  • FHIR 實戰工作坊：2026/09/29 (二) 10:00–16:30，民生科技服務大樓 102 會議室。
  • 科技照護戰情平台研討會：2026/10/29 (四) 10:00–16:30，民生科技服務大樓 101 會議室。

活動簡介 (Introduction)

隨著臺灣邁入超高齡社會，長期照顧服務之數位轉型與跨域資料整合成為關鍵課題。為建立全國一致之長照資料交換標準，2026 年度專案聯測聚焦於長照共通基礎資料層與實務核心業務情境。

本次專案聯測以 FHIR R4 標準為基礎，驗證五大主題：

  1. OAuth2 存取認證：提供安全的存取授權機制，作為各系統進行資料交換之共通前置基礎。
  2. 長照共通資料交換：建立跨居家照護、住宿機構、日間照護與在宅醫療共用之資料層，涵蓋病人基本資料、機構基本資料、生理量測、用藥紀錄、健康問題、照護目標、照護計畫、服務請求與照護執行紀錄等核心資源之標準建立、查詢與讀取。
  3. 居家照護資料交換：檢驗居家護理場域之個案基本資料、全人評估（健康紀錄評估）、照護計畫與共照記錄等四大情境之標準化新增與查讀。
  4. 長照服務費用支付審核：檢驗特約服務單位送出單筆長照費用申報，以及取得大會模擬審核結果之流程。
  5. 在宅急症照護資料交換：檢驗在宅急症「初次訪視與收案」、「持續訪視與急症治療」以及「後續照護安排與交班」三段臨床流程，涵蓋收案療程、實地訪視、急症評估與診斷、生理量測、處方與給藥、檢驗、處置、照護計畫、工作任務指派及交班紀錄之標準化建立與查讀。

運作機制說明 (Operation Mechanism)

聯測（Connectathon）為醫資標準化推動之重要驗證環節，確保參測單位之系統符合標準規範並具備跨系統資料互通能力。專案聯測（Projectathon）針對特定業務情境邀集產業界、政府公法人、長照機構與醫療院所共同參與，加速標準化落地應用。

本活動包含以下階段：

  • 聯測籌備小組：制定賽道規格、編製標準測資與環境、規劃驗收標準並公告參測指引。
  • 會前準備與預演：大會提前公告測試規範並開放測試主機，提供線上諮詢協助參測廠商完成系統介接預演。
  • 聯測現場執行：參測單位於現場 1.5 日內與大會端點或配對系統進行真實連線與資料交換測試，完成指定檢核項目。
  • 成果登錄公告：通過聯測檢核之產品與系統角色，於活動網站公開登錄。

賽道 (Tracks)

各賽道之情境、角色、交易與詳細操作步驟請參閱：

  • 賽道情境、角色與交易列表
  • 賽道 0：OAuth2 存取認證
  • 賽道 1：長照共通資料交換
  • 賽道 2：居家照護資料交換
  • 賽道 3：長照服務費用支付審核
  • 賽道 4：在宅急症照護資料交換

各賽道核心摘要：

  • Track 0：OAuth2 存取認證
    • 驗證系統取得與使用 OAuth2 Bearer Token 之標準流程。
    • 本賽道為共通前置賽道，參測系統取得有效 Token 後即可向 LTC Repository 存取受保護資源。
  • Track 1：長照共通資料交換
    • 驗證跨場域共用資料層之單一資源建立、查詢與讀取能力。
    • 包含病人基本資料（SC1）、機構基本資料（SC2）、生理量測（SC3）與用藥紀錄（SC4）四項必測，以及健康問題（SC5）、照護目標（SC6）、照護計畫（SC7）、服務請求（SC8）與照護執行紀錄（SC9）等選測項目，共 9 個情境。
  • Track 2：居家照護資料交換
    • 驗證居家護理場域之個案基本資料管理（必測）、全人評估管理（選測）、照護計畫管理（選測）與共照記錄管理（選測）之建立（POST）與查讀（Query / Retrieve），共 4 個情境。
  • Track 3：長照服務費用支付審核
    • 驗證長照特約服務單位送出單筆 BA07 服務費用申報，並銜接大會模擬審核服務查詢與取得審核結果。
  • Track 4：在宅急症照護資料交換
    • 驗證在宅急症初次訪視與收案（SC1）、持續訪視與治療（SC2）以及後續照護安排與交班（SC3）三段臨床流程之建立（POST）與查讀（Search / Read），共 3 個情境、20 筆交易。

參與單位與角色 (Participants & Roles)

  • 醫療服務提供者：醫院、診所與在宅醫療團隊，其醫療資訊系統參與在宅急症訪視紀錄產生與跨域轉銜。
  • 長期照顧服務機構：日間照護中心、居家護理所、居家服務機構、住宿型機構及 A 單位個管中心，參與長照共通資料建立與查讀、居家照護資料管理與費用申報。
  • 科技與資訊服務商：長照系統廠商、生理量測設備商、照護 App 開發商與費用申報軟體商，實作標準 FHIR API 介接。

涉及系統 (System Affected)

  • 長照個管與照護系統：負責查詢個案共通資料、登錄照護紀錄、填寫居護各項表單與銜接接續計畫。
  • 長照機構管理系統：負責維護機構資料、管理居護個案基本資料、全人評估、照護計畫與共照記錄，並辦理服務費用申報。
  • 在宅醫療資訊系統：負責建立在宅急症訪視與臨床紀錄，並供應接續照護計畫。
  • 長照資料交換中心：儲存與管理各項標準 FHIR 資源，提供查詢與資料供應服務。
  • 費用支付審核模擬服務：接收服務申報資料並依規則產出審核結果。

系統角色 (System Actors)

Keyword 名稱 說明
LTC_CONSUMER LTC Consumer 長照資料查詢端，負責發起條件查詢與單筆讀取請求，解析並呈現指定欄位。
LTC_MANAGEMENT LTC Management System 長照資料維護端，負責在長照共通資料交換與各業務賽道中發起單筆新增請求（POST）。
LTC_REPOSITORY LTC Repository 長照資料儲存端，負責提供標準資料交換與儲存服務，處理查詢、讀取與新增請求。
